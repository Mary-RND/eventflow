# Техническое задание: EventFlow

Учебный проект из курса: локальное браузерное приложение организатора мероприятия для управления списком участников. Все имена, компании и контакты в `data/` являются синтетическими учебными данными.

## Источник

Проектный бриф — `references/project-brief.md`. Критерии готовности — `references/acceptance-checklist.md`. Визуальный ориентир — `references/visual-reference.png` (не включается в приложение). Допустимые статусы и типы билетов заданы в `data/event-settings.json`. Если изображение противоречит текстовому брифу, главным является бриф.

## Демонстрационное событие

- Название: «Практикум „Продукты с ИИ“».
- Площадка: «Учебный центр».
- Вместимость: 120.
- Демонстрационные данные: `data/participants.csv` (12 корректных записей) и `data/participants-with-errors.csv` (2 корректные и 6 ошибочных строк).

## Функциональные требования (FR)

### FR-01. Главный экран

Главный экран показывает заголовок события и четыре показателя: всего активных, подтверждены, пришли, лист ожидания. Далее идут инструменты (поиск, фильтр статуса, фильтр билета, сортировка), кнопки «Добавить участника», «Импорт CSV», «Экспорт JSON», «Восстановить копию», таблица участников и компактный журнал последних действий.

### FR-02. CRUD участника

Участника можно добавить, открыть, изменить и архивировать. Архивация используется вместо необратимого удаления; из уведомления действие можно отменить. Модель участника: `id` (UUID), `name` (обязательная непустая строка), `email` (обязательный корректный email, уникальный без учёта регистра), `company` (необязательная), `ticket` (допустимое значение), `status` (`new`, `confirmed`, `waitlist`, `cancelled`), `checkedIn` (логическое), `registeredAt` (ISO-дата), `archivedAt` (`null` или дата).

### FR-03. Форма участника

Поля: имя, email, компания, тип билета, статус, отметка о прибытии. Имя и корректный email обязательны. Ошибки выводятся рядом с полем и объясняют, что исправить. Кнопка сохранения недоступна при заведомо неверных данных. Статус и тип билета выбираются только из допустимых значений (задаются `data/event-settings.json`). Check-in недоступен для неподтверждённого участника: `checkedIn: true` допустимо только для статуса `confirmed`. После успешного сохранения форма закрывается, таблица и показатели обновляются; та же форма используется для редактирования.

### FR-04. Поиск, фильтры и сортировка

Поиск работает по имени, email и компании. Работают фильтры статуса и типа билета. Работает сортировка по имени и дате регистрации (в обе стороны). Показатели пересчитываются после каждого изменения. Пустой результат поиска объясняет, как сбросить условия (кнопка «Сбросить фильтры»).

### FR-05. Импорт CSV

Пользователь выбирает CSV-файл и до изменения базы видит предпросмотр: сколько строк найдено, сколько корректно, сколько содержит ошибки, номер строки и понятную причину каждой ошибки, возможные дубликаты по email, кнопку импорта только корректных строк и кнопку отмены. До подтверждения ни одна строка не попадает в IndexedDB. Корректные строки импортируются одной транзакцией. Ошибочные строки в базу не попадают. Дубликаты по email не создаются. Результат сохраняется в журнале действий.

### FR-06. Резервная копия

Экспорт скачивает валидный JSON со свойствами `schemaVersion: 1`, `exportedAt`, `participants` и `activity`. Восстановление сначала проверяет структуру и версию файла, показывает число записей и предупреждает, что текущие данные будут заменены. Неверный или несовместимый JSON не меняет базу. Замена происходит только после отдельного подтверждения.

### FR-07. Журнал действий

Приложение ведёт журнал последних действий (добавление, обновление, архивация, отмена архивации, отметка о прибытии, импорт, восстановление). Журнал показывает краткое описание и время действия.

### FR-08. Состояния интерфейса

Реализованы состояния: `loading` (индикатор загрузки данных из IndexedDB), `empty` (нет участников; объясняется, как добавить первого участника или импортировать CSV), `error` (понятная причина при ошибке чтения файла или инициализации; база не изменяется), `success` (короткое уведомление-тост о результате действия). После архивации даётся возможность отменить действие.

### FR-09. Адаптивность

Интерфейс аккуратен и читаем на контрольных ширинах: 1440 px (десктоп), 768 px (планшет), 390 px (мобильный). Недопустимы горизонтальная прокрутка, наложение элементов и слишком мелкий текст.

### FR-10. Технические ограничения

Приложение использует только HTML, CSS и современный JavaScript без фреймворков. Запрещены npm/сборщики, внешние библиотеки, CDN, внешние шрифты, внешние API и серверная база. Приложение работает через локальный HTTP-сервер. Все пользовательские записи хранятся в IndexedDB. Структура приложения: `app/index.html`, `app/styles.css`, `app/db.js`, `app/app.js`.

### FR-11. Схема IndexedDB

База `eventflow-db` версии 1. Хранилище `participants` с ключом `id` (без автоинкремента) и индексами: `email` (уникальный), `status`, `registeredAt`, `archivedAt`. Хранилище `settings` с ключом `key`. Хранилище `activity` с ключом `id`. Операции, изменяющие несколько записей, выполняются одной транзакцией.
