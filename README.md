# EventFlow

Локальное приложение организатора мероприятия в одном браузере: превращает разрозненную таблицу регистраций в управляемый список участников. Без сервера и облака — все данные хранятся локально (IndexedDB).

Учебный проект с нуля: от брифа до критериев приёмки и acceptance-тестов (см. `docs/technical-specification.md` и `references/project-brief.md`).

## Возможности

### Главный экран
- заголовок события и краткие настройки;
- четыре показателя: всего активных, подтверждены, пришли, лист ожидания;
- поиск по имени, email и компании;
- фильтр по статусу и типу билета;
- сортировка по имени и дате регистрации;
- таблица участников с действиями: открыть, изменить, отметить приход, архивировать;
- кнопки «Добавить участника», «Импорт CSV», «Экспорт JSON», «Восстановить копию»;
- журнал последних действий.

### Форма участника
Поля: имя, email, компания, тип билета, статус, отметка о прибытии. Обязательные поля обозначены, ошибки показываются рядом с полем с подсказкой, кнопка сохранения недоступна при заведомо неверных данных. Форма переиспользуется для редактирования.

### Импорт CSV
До изменения базы отображаются:
- сколько строк найдено, корректно и с ошибками;
- номер строки и понятная причина каждой ошибки;
- возможные дубликаты по email;
- кнопка импорта только корректных строк и кнопка отмены.

Корректные строки записываются одной транзакцией; ошибочные в базу не попадают. Результат фиксируется в журнале действий.

### Резервная копия
- экспорт JSON со свойствами `schemaVersion`, `exportedAt`, `event`, `participants`, `activity`;
- восстановление с проверкой структуры и версии, количеством записей и отдельным подтверждением замены.

### Пустые и ошибочные состояния
- инструкция при первом запуске;
- подсказка сброса фильтров при пустом поиске;
- понятная причина при ошибке чтения файла (база не меняется);
- уведомления о результате действий и отмена архивации.

## Технологии

| Компонент | Технология |
|---|---|
| Языки | HTML, CSS, JavaScript |
| Хранилище | IndexedDB (`app/db.js`) |
| Сборка | не требуется (без npm) |
| Код | `app/app.js`, `app/db.js` |
| Тесты | `pytest` + `node --check` (acceptance-тесты) |

## Установка и запуск

Приложение статическое. Откройте `app/index.html` в браузере либо запустите локальный сервер:

```bash
python serve.py
# или
node serve.mjs
```

Демо-данные для импорта: `data/participants.csv` и `data/participants-with-errors.csv`.

## Тесты

```bash
pip install -r requirements-dev.txt
node --check app/db.js
node --check app/app.js
pytest -v
```

Acceptance-тесты проверяют критерии приёмки (`tests/test_acceptance.py`, ветка `feature/acceptance-tests`). Шаблон CI: `docs/ci.yml.example`.

## Разработка (git-flow)

- `main` — релизная ветка;
- `develop` — интеграционная ветка;
- `feature/*` — ветки функций (объединяются через pull request).

## Ограничения

- Рассчитан на одного организатора: без аккаунтов, ролей и облачной синхронизации.
- Данные локальные: приложение не предназначено для хранения реальных персональных данных.
